# Staff MFA session issuance — backend-only

`createStaffAuthStore({ pool, businessId, totpStore })` now provides `authenticateWithTotp({ email, password, code })`. It verifies the tenant-scoped, enabled, email-verified staff account and scrypt password under a database transaction, then consumes a valid active TOTP code **before** inserting the hashed 12-hour session. Wrong, missing, used or foreign TOTP codes never produce a session. Two concurrent attempts with one code can create at most one session. The legacy `authenticate` method rejects `MFA_REQUIRED` whenever a TOTP store is configured; it cannot downgrade that store to password-only.

This module is NOT wired to HTTP, does NOT serve a browser form and does NOT send/issue a cookie. The existing `app.js` does not yet configure a TOTP store. Never connect a public route to the legacy password-only method; it remains for isolated/trusted tests only. Before any browser login endpoint is enabled, wire a trusted, separate `FACTURATIONS_TOTP_ENCRYPTION_KEY` to the tenant's TOTP store and require MFA for all enabled staff. Call the business-scoped PostgreSQL login limiter `reserve(email)` before password verification and `reset(email)` only after fully verified MFA and successful session issuance; enforce an independent trusted-edge IP limit as well. Implement strict HTTPS/Origin/CSRF and private `Secure; HttpOnly; SameSite=Strict` cookie issuance, proper logout, an independently verified owner/staff enrollment ceremony and recovery/key rotation procedures. Test sessions, CSRF, unexpected errors and tenant denial end to end on the separate staging host before deployment.

Migration 007 must be applied only to the dedicated Facturations database. All tests use synthetic users, key and disposable localhost PostgreSQL 16. This implementation does not interact with Wave, email, payments or any GROUPE TAKATAK production system.
