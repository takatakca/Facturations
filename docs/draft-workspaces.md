# Private revisioned draft workspace — backend foundation only

This is NOT invoice issuance, browser autosave or a published API. `src/draft-workspace-store.js` implements backend-only `create`, `load`, and `save` for one authenticated staff member in one configured business. The service requires a current staff bearer token: it hashes and verifies the token against an unexpired, unrevoked PostgreSQL session and an enabled, verified staff account **inside the same transaction** as a write. A workspace belongs to its creating staff member; colleagues, other businesses and revoked sessions cannot retrieve or overwrite it. Never accept a tenant ID or staff ID from an HTTP request to choose the scope. Browser endpoints must separately enforce origin, CSRF, size limits and role policy before invoking this service.

## Revision and privacy contract

Migration `db/008_draft_workspaces.sql` creates a separate mutable work-in-progress workspace and immutable append-only revision history; it does not change `invoice_drafts` or its immutable snapshot protection. A new workspace has revision 1. `save` requires an exact `expectedRevision`; concurrent tabs editing the same revision result in one saved revision and one `WORKSPACE_REVISION_CONFLICT` (409). The caller must load the current version and explicitly resolve differences; never automatically replace its unsaved local changes. Each create has a staff-scoped creation key: retries with the same original content return the existing workspace, even after later edits; the same key with different initial content is a conflict. PostgreSQL transaction rollback prevents a revision update without its matching history row. Workspaces are never invoices, revenue, approved content or emailed content.

Content is bounded JSON (24 KB serialized before DB, DB size backstop 32 KB), restricted to fields used for drafting (`currency`, `customer`, `invoiceDate`, `dueDate`, `notes`, `lines`, `taxes`). Partial/incomplete fields are allowed while editing. This does NOT mean the content is a valid invoice; before any future snapshot creation call `previewDraft` to validate and recalculate amounts, and require separate owner approval of the exact snapshot. Do not cache workspace contents in persistent browser storage or include them in public logs, URLs or telemetry.

## What remains before user-visible autosave

Add audited, cookie-authenticated, CSRF-protected editing endpoints; a responsive FR/EN form with honest Saving/Saved/Offline/Conflict states; reload/recovery and conflict-resolution UX; tested browser/DB integration and access revocation; provisioning/recovery; isolated MochaHost staging. Do not deploy this migration to an existing TAKATAK database. No Wave write, PDF, real email, actual customer or payment is accessed by this service.
