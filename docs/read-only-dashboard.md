# Bilingual read-only dashboard — implementation and release limits

`GET /internal/dashboard?lang=fr` (or `lang=en`) renders a responsive, server-side HTML view from the same tenant-scoped PostgreSQL summary and recent-draft list as the JSON API. It has no scripts, external assets, browser-stored tokens or invoice-writing actions. Customer email, street address, full invoice contents, Wave credentials and internal approval details are not included. Draft totals are **never** presented as issued invoices, payments or revenue.

## Access and sign-out

The dashboard requires a valid, unexpired, unrevoked staff session scoped to the configured business. The read-only browser integration accepts a `__Host-` HttpOnly, Secure, SameSite=Strict session cookie issued only after password and TOTP validation, when a dedicated PostgreSQL database, HTTPS origin and login limiter are correctly configured. The existing bearer-token integration remains supported for private service use. `X-Admin-Key` cannot access the HTML page and cannot serve as a fallback. Never put a token in a URL, browser script, localStorage, screenshot, commit or public issue.

The header provides a **Se déconnecter / Sign out** button. Its single HTML form POSTs to the existing `/internal/logout?lang=fr|en` route; no credential or invoice data are embedded in its markup. Logout checks the exact configured HTTPS Origin and Host, refuses cross-site requests, revokes the presented session in PostgreSQL and clears the browser cookie before redirecting to login. GET logout is refused. If the revocation database call fails, the route responds with an error rather than falsely claiming that logout succeeded. The dashboard Content Security Policy allows `form-action 'self'` solely to support this same-origin form, while scripts, external connections and frames stay disabled. HTML escapes customer-controlled text and is marked `private, no-store`.

## Test and release limits

Synthetic unit/HTTP tests exercise both languages, HTML escaping, denied requests, form action, same-origin POST logout, cross-origin refusal and session revocation. Existing PostgreSQL tests cover tenant-scoped dashboard data sources and staff sessions. This is **not** a completed billing workspace or an approved public release: it has no invoice editor, issuance, Wave writes, PDF, email or customer portal. Owner enrollment, safe MFA provisioning and recovery, complete browser E2E tests, reverse-proxy/TLS verification and an isolated staging sign-off remain outstanding. No MochaHost deployment, client communication or actual invoice issuance is included. Never migrate an existing TAKATAK production database.
