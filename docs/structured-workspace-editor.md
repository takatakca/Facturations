# Structured browser working draft — review-only increment

This PR is **stacked on #44, #43 and #42**. The existing session-guarded `/internal/editor` now presents FR/EN fields for customer name/email/address, invoice/due dates, notes, **up to five line items**, and up to three **explicitly entered** tax definitions. It updates only `facturations_draft_workspaces`, not official `invoice_drafts`. All saves remain manual, owner-staff scoped, same-origin and CSRF-protected, with optimistic `expectedRevision`; HTTP 409 preserves unsaved user input. The list and read-only server-calculated preview in #43/#44 can then be used after a complete working draft has been saved.

Amounts are parsed from decimal strings (dot or comma), converted to integer CAD cents **without floating-point multiplication**, then validated against the preview engine's limits. Tax rates are entered as percentages with up to three decimal places and converted to milli-percent; **no rate is preselected and taxable flags are explicit**. Blank line and tax slots are omitted. Partially completed workspaces can be saved without dates, email, line items or taxes; **the separate server preview refuses incomplete content with 422**, never showing invented totals. This editor cannot establish tax registration, exemptions, jurisdiction, or legal invoice compliance; qualified review is needed before issuance.

This deliberately bounded first screen supports at most five lines. If an existing workspace has more than five lines, more than three taxes, unexpected nested line/tax fields, or incompatible types, the client disables edits rather than silently dropping hidden financial data. Root metadata and customer metadata not displayed remain preserved. The UI does not save to localStorage/sessionStorage, does not embed staff credentials in HTML, and does not send any content to Wave, email, a PDF generator or a payment provider.

Automated tests cover FR/EN markup, field conversion and server totals on synthetic `example.test` data, reload, preserved fields, conflicts, and invalid amounts, tax percentages and dates rejected before writes. These are Node HTTP/VM tests, **not browser/mobile/accessibility tests**. The production prerequisites remain branch protection (#41), independent review, isolated HTTPS staging with tested MFA provisioning/recovery and backup restoration, current tax/accounting validation and explicit authorization for each external action. No merge or deployment is part of this PR.
