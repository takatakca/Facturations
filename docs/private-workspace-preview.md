# Private calculated preview for a saved working draft

This increment is **read-only** and **not an invoice**. It depends on PR #43 (recent workspaces), which depends on PR #42 (first staff browser editor). Once all three are reviewed, integrated and exercised on a separately authorized HTTPS staging deployment, a signed-in OWNER/STAFF member may select **Aperçu calculé (si complet) / Calculated preview (if complete)** beside a saved working draft. The link contains only a workspace UUID and a FR/EN language value.

`GET /internal/workspaces/<uuid>/preview?lang=fr|en` reads the original owner's workspace through `createDraftWorkspaceStore.load`, which rechecks the active, verified, enabled tenant-scoped staff session in PostgreSQL. No admin header, bearer token, arbitrary tenant or submitted amounts are accepted. It then calls the existing `previewDraft` function **on the stored revision**, using integer CAD cents and only the tax definitions and taxable flags explicitly present in that revision. It does not assume a provincial tax rate, validate tax applicability, create `invoice_drafts`, issue a number, update the workspace, call Wave, send email or collect payment.

The bilingual, print-friendly HTML escapes all customer-provided fields, displays the stored revision, itemized quantities/prices/discounts, separately calculated taxes and total, and labels the result **PREVIEW ONLY**. Private `no-store`, no-referrer, no-script CSP and frame denial apply; the response contains no session or CSRF token. If a notes-only workspace has no complete customer contact, dates, lines or explicit `taxes` array, the route returns HTTP 422 with an *incomplete* explanation **without suggesting a monetary total**. The current editor cannot enter all required invoice fields yet: this link is preparatory, not a claim that all existing workspaces can be priced.

**Automated evidence:** `tests/browser-workspace-preview.test.js` verifies server-side calculation, hostile HTML escaping, language links, refused methods/query/admin/bearer/missing cookies, incomplete content and injected outages. With disposable PostgreSQL 16 it also verifies owner-only access, same-business colleague denial, cross-business denial, revoked sessions and no official invoice creation. Test fixtures contain only fictional `example.test` data. Node/HTTP tests do not replace real FR/EN browser, mobile, accessibility, TLS reverse proxy, data retention or tax/accounting review.

**Remaining release gates:** independently review and protect `main` (issue #41); integrate PRs #34–#37, #39–#40 and #42–#44 in dependency order; run CI on the final integration SHA; validate an isolated HTTPS staging and a complete form for customer email/address, dates, line items and explicit taxes; obtain owner approval before any actual invoice issuance or separate delivery. Never deploy into an existing GROUPE TAKATAK service or use real customer data on the basis of this PR.
