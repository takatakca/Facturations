# Brouillon enregistré → copie immuable → approbation interne : test lié

Le test `tests/workspace-submission-approval-journey.test.js` utilise **uniquement** `FACTURATIONS_TEST_DATABASE_URL` pointant vers `localhost/facturations_test`, le schéma 001–009, un propriétaire et un client fictifs `example.test`. Il appelle les véritables magasins PostgreSQL dans **la même session propriétaire**. Il vérifie que la soumission explicite crée une copie immuable et un événement `DRAFT_CREATED` mais **aucune approbation automatique**; une approbation distincte sur un mauvais total est refusée; la bonne approbation est idempotente; la copie et le lien restent uniques; l'espace initial refuse toute modification après soumission (409); la révocation bloque les deux opérations. Le brouillon immuable demeure `DRAFT` : ni émission, ni Wave, ni courriel, ni paiement.

**Ne pas confondre la couverture :** ce test appelle des services internes depuis Node. Il ne remplace pas un parcours Chrome passant par les véritables formulaires et routes HTTPS, ni une authentification MFA au sein de ce même scénario. Le scénario Chrome complet a été tenté mais son ajout a été refusé par le contrôle de sécurité de l'outil; aucune preuve Chrome nouvelle ne doit être revendiquée. Les tests Chrome préexistants peuvent rester verts sans couvrir cette jonction. L'essai avec certificat public, proxy réel et base de préproduction isolée reste à réaliser, ainsi que revue indépendante et protection `main` (#41).
