# Recent private workspaces — bounded navigation increment

The FR/EN dashboard now links to `/internal/recent-workspaces?lang=fr|en`. This private, server-rendered page lists at most **20** recently updated work-in-progress records owned by the **currently authenticated staff member within the configured business**. The customer name is escaped before HTML rendering. Rows contain only workspace UUID, customer name, revision and update time; no notes, full customer contacts, tax details, session tokens or CSRF tokens appear in the listing. Links carry only a non-secret UUID and language and reopen `/internal/editor` from PR #42, where the backend independently checks live session and ownership again. A missing workspace or another employee's ID cannot grant access.

`src/recent-workspace-store.js` checks staff-session validity, verified email, enabled state, OWNER/STAFF role, revocation, expiry, business and original workspace ownership **within one SQL statement**. An unauthorized session gets 401 even when no records exist. PostgreSQL errors produce 503 without leaking a connection string or customer data. The page rejects bearer and `X-Admin-Key`, unexpected methods or query parameters; it sends `private, no-store` and a no-script CSP. This is **not** an invoice search, customer directory, approval queue or issuance control. Its listing is deliberately limited, without pagination or deletion.

CI tests use synthetic `example.test` data and isolated disposable PostgreSQL 16 to verify cross-staff/tenant denial, revocation and metadata minimization. Actual mobile, keyboard, screen-reader, TLS/proxy, backup/restore and recovery from an ambiguous *first* creation remain untested until an independently approved HTTPS staging environment exists. The related PR is stacked on #42 and cannot be merged independently into `main` without #42; require review, GitHub `main` protection (#41), combined CI after integration, and owner sign-off. No Wave writes, invoice issuance, payments, emails or production changes.
