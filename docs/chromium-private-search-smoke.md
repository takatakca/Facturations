# Essai navigateur de la recherche privée FR/EN — en revue

PR empilée sur #52. `scripts/browser-smoke-workspace-search.js` exécute **Chromium réel** deux fois (FR puis EN) et charge le vrai HTML de `renderRecentWorkspaces` via la vraie route `attachBrowserRecentWorkspaces`. Un script de test sur une page distincte charge les 20 premiers résultats, extrait le vrai formulaire de recherche, saisit un fragment fictif `Archive_%`, puis soumet ce formulaire par navigation POST. Le rendu final doit présenter uniquement le brouillon ancien correspondant, avec son nom échappé et son lien d'éditeur sans données privées dans l'URL. Le service vérifie le cookie `Secure` de test et les en-têtes Origin/Host; aucun changement du code applicatif n'est requis.

Le test démarre **uniquement sur 127.0.0.1** en HTTPS avec certificat auto-signé et clé créés à l'exécution dans un dossier temporaire, effacés ensuite. Le contournement de validation du certificat est limité au processus Chrome du test; il n'est jamais une configuration recommandée pour préproduction/production. Les sessions et le stockage sont simulés, pas issus d'un MFA réel ni de PostgreSQL. La suite Node/PostgreSQL de #52 teste séparément les restrictions employé/entreprise, mais le navigateur ne les teste pas ensemble. La validation HTTPS réelle sur `facturations.bolon.ca`, la chaîne proxy/certificat de confiance, les parcours MFA, les droits avec PostgreSQL réel et une revue indépendante restent indispensables. Aucune donnée client, facture émise, écriture Wave, courriel, paiement, fusion ni déploiement.
