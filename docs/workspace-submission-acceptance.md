# Saved workspace → immutable internal draft (OWNER only)

This increment connects the previously disjoint working editor and immutable owner review without issuing an invoice. An OWNER opens the saved version's calculated preview, follows **Prepare for internal review**, reviews the *saved revision*, explicitly checks confirmation, and POSTs the same-origin form. The server rechecks the live OWNER session and original workspace ownership, exact revision, recipient email and server-calculated total. A single PostgreSQL transaction locks the session and workspace; inserts customer, immutable `invoice_drafts`, `DRAFT_CREATED` audit event and one-to-one immutable source mapping; then freezes the original workspace. An identical concurrent retry returns the same draft ID. A changed revision, foreign owner/tenant, stale amount, revoked session or malformed CSRF must fail closed. No browser state contains a provider credential.

Apply `db/009_workspace_submissions.sql` **only to the dedicated new Facturations DB**, after migrations 001–008. The isolated test setup applies it only to localhost `facturations_test`. Once submitted, the original working draft cannot be edited; to change the submitted content, create a new working draft and repeat review. The immutability trigger protects even against accidental direct SQL updates. Only the original OWNER of a workspace can submit it in this increment: STAFF-authored workspaces cannot be promoted by another owner yet. That handoff requires a separate, audited ownership/approval design.

The saved-preview navigation link is displayed only for live OWNER sessions, and the `/internal/submit/<uuid>` route enforces OWNER independently. Redirect after submission goes to the existing internal `/internal/review/<uuid>` route; **that separate step** requires its own four acknowledgements and existing append-only approval transaction. Submitting does not itself approve. No issuance, official numbering, Wave write, PDF, email, payment or customer portal is implemented or authorized here.

Evidence must include `npm run check`, Node 20/22, isolated PostgreSQL 16 integration tests, existing Chromium suites and ideally a dedicated browser end-to-end test of the entire new path. Real `facturations.bolon.ca` hosting, public TLS and proxy configuration, independent review, `main` protection, backup/restore and tax/accounting review are **not** established by local test fixtures. This feature remains draft-only until those gates are met.
